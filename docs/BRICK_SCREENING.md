# 新零件筛选：哪些常用砖能测、最常见的是哪些（2026-11-05）

## 1. 能测的范围
BrickGPT 的文字格式和 Gurobi 稳定性检查只支持**高度一格、长方形、有凸点的标准砖**。每块砖只有长、宽、朝向三个参数（`stability_analysis.py` 只读 `height`、`width`、`ori`）。

- **不改代码就能测：** 长方形标准砖。
- **要改代码：** 转角砖（L 形）、薄板（1/3 砖高）、高砖（1x2x2 等）、拱砖、斜面砖。
- 空心砖（1x2 hollow 等）在受力上和普通砖一样，没有测的意义。

## 2. 目前在产的普通砖一共 16 种（Brick Architect 目录"Brick"类）
1x1、1x2、1x3、1x4、1x6、1x8、1x10、1x12、1x16、2x2、2x2 转角、2x3、2x4、2x6、2x8、2x10。
- BrickGPT 已有 8 种：1x1、1x2、1x4、1x6、1x8、2x2、2x4、2x6。
- **没有的 8 种：** 1x3、2x3、1x10、1x12、1x16、2x8、2x10，以及 2x2 转角砖。
- 4x6（2356）已在 2010 年停产；普通的 4x4 方砖不存在（4x4 只有薄板、转角砖、圆砖）。

## 4. 训练数据从哪来：不用合并法
**合并法**（把数据集里相邻的两块砖拼成新零件）**不适合做正式训练数据**：
- 它只是把原结构换个写法。模型学到的是"1x1 + 1x2 可以写成 1x3"，而不是"新零件该放在哪里、能起什么作用"。
- 结构本身是为原来 8 种砖设计的，新零件只出现在碰巧能合并的地方。garbage in, garbage out。
- pilot（`pilot/RESULTS.md`）用的是合并法，所以 pilot 的结论（"模型几乎不用 1x3"）只能说明 prompting 不够，不能用来评估训练效果。

**正式方案（阶段 2，`newbrick/build_stage2_data.py`）用重新拼法：**
- 取数据集里每个结构的体素形状，用原作者自己的拼法算法（STABLE 仓库里的 mesh2brick），在**加入新零件的积木库**上重新拼 K 次，再用 Gurobi 选出最稳的一种。
- 这和原数据集 StableText2Brick 的生成方式相同（原数据也是 mesh2brick 拼出来、再按稳定性筛选的），所以新零件出现在拼法算法认为合适的位置，不是硬凑出来的。
- 数据量不受限制：任何体素形状都能重新拼。

附：合并法的统计（`newbrick/merge_coverage.py`，500 个 test 结构，平均每个结构有几对砖能拼成该尺寸）。只能用来粗略反映这个尺寸在现有结构里"有多少空间"，**不作为筛选标准**：
1x3 4.92、2x3 3.80、2x8 2.72、2x10 1.91、1x10 1.69、1x12 1.15、1x16 0.59、4x6 7.74。

## 6. 建议
综合"常见程度"和"物理上有没有用"两方面（训练数据用重新拼法，不受零件种类限制）：
1. **1x3**：最常见、能直接测。物理上的好处只有省砖。
2. **2x2 转角砖**：第二常见，而且是唯一有明确受力理由（加固墙角）的候选。代价是要改稳定性检查和文字格式。
3. **2x3**：和 1x3 情况相近，可以作备选。
其余长方形砖（2x8 及以下）不够常见，而且实验显示它们也不能让结构更稳，还让抗扰动能力变差，不建议选。
长方形新砖已经全部测完（8 组，见 `newbrick/STAGE1_REPORT.md`），**没有一种能让结构显著更稳**。所以如果项目要讲"新零件让结构更稳"，只剩转角砖这类非长方形零件；如果选 1x3，就只能讲"省砖"。
